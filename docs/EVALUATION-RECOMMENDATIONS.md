# Recommendation evaluation on synthetic data

Generated by `npm run recommend:evaluate -w apps/api` (pure, in-memory; no database). Dataset `synthetic-v2`, seed 20261117: 908 users, 36 tracks, 52126 counted events. Everything here is **synthetic demonstration data**; it verifies that the method behaves as designed, not how real listeners respond.

## Protocol

One global chronological split by event time: training before 2026-10-30 21:37 UTC (36488 events), validation until 2026-11-05 11:06 UTC (5212), test after (10426). Taste vectors, neighbours, popularity and the training catalog (36 tracks) use training data only. Relevant tracks = tracks in a user's held-out events that the user had not heard in training. Tracks first appearing after training: 0 (excluded). Users with held-out events but no eligible relevant track: 57 (excluded). Metrics at K = 10; Precision@10 always divides by 10.

## Interpretation limits

The generator plants genre preferences, so genre-based neighbours have a structural advantage here; a real catalogue with richer taste would test the method harder. The catalogue is small (36 tracks) and users have already heard many of them, so K = 10 covers a large share of the remaining candidates and recall is high for both methods. Tracks that surge only after the training period (the planted breakouts) are hard for both methods, because both learn from training data only. Validation differences between neighbour counts of 20 and 40 are small, so the choice is not sharply determined. Relevance comes from listening only (no ratings). Results come from one seed; the bootstrap reflects user sampling, not generator randomness.
